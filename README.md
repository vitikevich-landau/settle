# settle

Запускайте функции конкурентно через знакомые комбинаторы `AllSettled`, `All`, `Race` и `Any`. Если готового правила недостаточно, переходите на низкоуровневый `Stream` и обрабатывайте результаты по мере готовности.

```go
values, err := settle.All(ctx, tasks...)
if err != nil {
    return err // остальные задачи уже отменены и завершены
}
use(values)
```

Все обёртки реализованы поверх `Stream`: механизм запуска, отмены, перехвата паник и ожидания горутин в пакете один.

## API

```go
func AllSettled[T any](ctx context.Context, fns ...func(context.Context) (T, error)) []Result[T]
func All[T any](ctx context.Context, fns ...func(context.Context) (T, error)) ([]T, error)
func Race[T any](ctx context.Context, fns ...func(context.Context) (T, error)) (T, error)
func Any[T any](ctx context.Context, fns ...func(context.Context) (T, error)) (T, error)

func Stream[T any](ctx context.Context, fns ...func(context.Context) (T, error)) iter.Seq2[int, Result[T]]

type Result[T any] struct {
    Value T
    Err   error
}

type PanicError struct { // задача запаниковала; доставляется через Result.Err
    Value any
    Stack []byte
}
func (p *PanicError) Unwrap() error // panic(err) прозрачен для errors.Is / errors.As

var ErrGoexit error // задача завершила горутину через runtime.Goexit (t.Fatal и т.п.)
var ErrNoTasks error // Race или Any вызваны без задач
```

## Контракт

- **Одна горутина на задачу.** Все функции запускаются конкурентно при вызове готового комбинатора или при начале обхода `Stream`.
- **Ранний результат означает отмену.** `All`, `Race` и `Any` отменяют задачи, которые больше не могут повлиять на ответ, и перед возвратом дожидаются их завершения.
- **Задачи обязаны уважать `ctx`.** Отмена кооперативна: если функция игнорирует контекст, комбинатор будет ждать её обычного возврата.
- **`Result` не зануляет значение при ошибке.** `AllSettled` и `Stream` сохраняют в `Result.Value` ровно то, что вернула задача; `Race` так же сохраняет пару `(T, error)` победителя. `All` и `Any` по своей семантике не отдают значения провалившихся задач.
- **Ровно один `Result` на задачу.** Паника внутри задачи не убивает процесс, а становится `*PanicError` в `Result.Err`; задача, завершившая горутину через `runtime.Goexit` (например, `t.Fatal` внутри теста), даёт `Result` с ошибкой `ErrGoexit`. Соседние задачи в обоих случаях не затрагиваются.
- **Структурная конкурентность.** Когда вызов комбинатора или цикл по `Stream` закончился, ни одна запущенная им горутина уже не работает.

## Семантика комбинаторов

| Функция | Когда заканчивается | Результат | Пустой список |
| --- | --- | --- | --- |
| `AllSettled` | завершились все задачи | `[]Result[T]` в порядке аргументов; ошибки лежат рядом со значениями | пустой срез |
| `All` | завершились все или получена первая ошибка | `[]T` в порядке аргументов; при ошибке — `nil` и обёрнутая индексом причина | пустой срез, `nil` |
| `Race` | завершилась первая задача | её `(T, error)`, независимо от успеха | `ErrNoTasks` |
| `Any` | получен первый успех или упали все | первый успешный `T`; иначе `errors.Join` ошибок в порядке аргументов | `ErrNoTasks` |

«Первая ошибка» у `All` означает первую полученную по времени, поэтому её индекс при нескольких одновременных сбоях может различаться. `Any`, напротив, перед `errors.Join` раскладывает ошибки по исходным индексам, чтобы итоговый текст и обход `Unwrap() []error` были стабильны.

## Когда нужен Stream

Используйте готовые комбинаторы по умолчанию. `Stream` нужен, если:

- результат важно обработать сразу, не дожидаясь всей пачки;
- решение зависит от индекса или источника задачи;
- правило остановки предметное: например, ошибка рекомендаций допустима, а ошибка заказов фатальна;
- нужна ленивая последовательность, которую можно обойти повторно и тем самым заново запустить задачи.

```go
loop:
for i, result := range settle.Stream(ctx, tasks...) {
    if result.Err != nil && required[i] {
        break loop // отменяет и дожидается остальных
    }
    handle(i, result)
}
```

`Stream` выдаёт результаты в порядке завершения вместе с индексом исходной задачи. Запуск ленивый: функции стартуют при начале `for range`, а каждый новый обход последовательности запускает их заново. Выход через `break` отменяет незавершившиеся задачи, ждёт их возврата и отбрасывает результаты, созревшие после остановки.

Работающие примеры всех четырёх обёрток и отдельный пример собственной политики на `Stream` лежат в [`example_test.go`](example_test.go) и отображаются как документация на pkg.go.dev.

Живая демонстрация всех сценариев — включая таймаут через контекст и перехват паник — в [`examples/main.go`](examples/main.go):

```sh
go run ./examples
```

## Боевые сценарии

Примеры выше показывают механику: задачи просто спят и возвращают строку. В [`examples/realworld/`](examples/realworld) те же приёмы применены к работе, которая встречается в проде, — с настоящими HTTP-запросами, настоящим чтением файлов и настоящими дедлайнами:

```sh
go run ./examples/realworld
```

| Файл | Задача | Что показывает |
| --- | --- | --- |
| [`bff.go`](examples/realworld/bff.go) | собрать страницу из трёх микросервисов | `Stream`: своя политика обязательных и необязательных фрагментов, обработка по мере готовности |
| [`failover.go`](examples/realworld/failover.go) | прочитать данные из нескольких реплик | `Any`: первый успех побеждает; hedged requests — отложенный старт дублей; `errors.Join` вместо `AggregateError` |
| [`health.go`](examples/realworld/health.go) | ручка `/readyz` | `AllSettled`: полный отчёт по всем зависимостям в рамках общего дедлайна |
| [`checksums.go`](examples/realworld/checksums.go) | SHA-256 для пачки файлов | `AllSettled` пачками: ограничение конкурентности через `slices.Chunk`; отменяемый ввод-вывод |
| [`signup.go`](examples/realworld/signup.go) | проверки при регистрации | `All`: первый отказ отменяет платный вызов антифрода; бизнес-отказ (400) против поломки (503) |

Внешняя сеть не нужна: «микросервисы» поднимаются локально через `httptest`, файлы создаются во временной директории. Программа одинаково работает офлайн и в CI.

## Заметки о дизайне

- **Один механизм конкурентности**: `AllSettled`, `All`, `Race` и `Any` — короткие циклы поверх `Stream`, без собственного scheduler-кода.
- **Одна горутина на задачу**, как у промисов в JS. Без пула воркеров, без опций — сознательно.
- **Канал результатов с буфером `len(fns)`**: воркер всегда может положить результат и выйти, даже если потребитель давно ушёл. Никто не блокируется на отправке, никто не утекает.
- **Отправка результата — в `defer`**: она происходит даже если задача завершает горутину через `runtime.Goexit`, поэтому потребитель никогда не зависает в ожидании недостающего результата.
- **Fan-in перед yield**: воркеры пишут в канал; `yield` вызывает единственный цикл. Параллельные вызовы `yield` нарушают контракт итератора.
- **Порядок уборки важен**: при выходе итератор сначала отменяет (`cancel`), потом ждёт (`wg.Wait`). См. пару `defer` в `Stream`.

## Требования

Go 1.23+ (итераторы range-over-func).

## Тестирование

```sh
go test -race ./...
```

Тесты проверяют гарантию отсутствия утечек, отслеживая число горутин. Для более строгой проверки подключите [goleak](https://github.com/uber-go/goleak):

```go
func TestMain(m *testing.M) {
    goleak.VerifyTestMain(m)
}
```
