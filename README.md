# settle

Запускайте функции конкурентно и потребляйте результаты **по мере их готовности** — через нативный итератор Go.

Один примитив: `Stream`. Каждый классический комбинатор промисов из JS (`all`, `allSettled`, `race`, `any`) — это просто цикл `for range` по нему. Выход из цикла через `break` **отменяет оставшиеся задачи** — то, чего `Promise.all` не умеет в принципе.

```go
for i, r := range settle.Stream(ctx, tasks...) {
    if r.Err != nil {
        break // отменяет всё, что ещё выполняется
    }
    use(i, r.Value)
}
```

## API

```go
func Stream[T any](ctx context.Context, fns ...func(context.Context) (T, error)) iter.Seq2[int, settle.Result[T]]

type Result[T any] struct {
    Value T
    Err   error
}

type PanicError struct { // задача запаниковала; доставляется через Result.Err
    Value any
    Stack []byte
}
func (p *PanicError) Unwrap() error // panic(err) прозрачен для errors.Is / errors.As

var ErrGoexit error // задача завершила горутину через runtime.Goexit (t.Fatal и т.п.)
```

## Контракт

- **Запуск ленивый.** Задачи стартуют не при вызове `Stream`, а в момент обхода итератора (`for range`). Каждый новый обход возвращённой последовательности запускает все задачи заново — результаты не мемоизируются.
- **Порядок завершения**, а не порядок аргументов. Какая задача дала результат — определяет индекс.
- **`break` = отмена.** Выход из цикла отменяет контекст, переданный оставшимся задачам, и дожидается их возврата. Результаты, «созревшие» после `break`, молча отбрасываются — включая ошибки и паники.
- **Ровно один `Result` на задачу.** Паника внутри задачи не убивает процесс, а становится `*PanicError` в `Result.Err`; задача, завершившая горутину через `runtime.Goexit` (например, `t.Fatal` внутри теста), даёт `Result` с ошибкой `ErrGoexit`. Соседние задачи в обоих случаях не затрагиваются.
- **Структурная конкурентность.** К моменту выхода из range-цикла — обычного или через `break` — ни одна горутина, запущенная итератором, уже не работает. Чтобы завершение было быстрым, задачи обязаны реагировать на отмену `ctx`.

## Комбинаторы — это циклы

| JS                   | Go                                                            |
| -------------------- | ------------------------------------------------------------- |
| `Promise.allSettled` | пройти цикл до конца, собрать каждый `Result`                 |
| `Promise.all`        | `break` на первой ошибке (отменяет остальных)                 |
| `Promise.race`       | взять первую пару, `break`                                    |
| `Promise.any`        | `break` на первом `Err == nil`                                |

Работающие версии всех четырёх лежат в [`example_test.go`](example_test.go) и отображаются как документация на pkg.go.dev.

## Заметки о дизайне

- **Одна горутина на задачу**, как у промисов в JS. Без пула воркеров, без опций — сознательно.
- **Канал результатов с буфером `len(fns)`**: воркер всегда может положить результат и выйти, даже если потребитель давно ушёл. Никто не блокируется на отправке, никто не утекает.
- **Отправка результата — в `defer`**: она происходит даже если задача завершает горутину через `runtime.Goexit`, поэтому потребитель никогда не зависает в ожидании недостающего результата.
- **Fan-in перед yield**: воркеры пишут в канал; `yield` вызывает единственный цикл. Параллельные вызовы `yield` нарушают контракт итератора.
- **Порядок уборки важен**: при выходе итератор сначала отменяет (`cancel`), потом ждёт (`wg.Wait`). См. пару `defer` в `Stream`.

## Требования

Go 1.23+ (итераторы range-over-func).

## Тестирование

```sh
go test -race ./...
```

Тесты проверяют гарантию отсутствия утечек, отслеживая число горутин. Для более строгой проверки подключите [goleak](https://github.com/uber-go/goleak):

```go
func TestMain(m *testing.M) {
    goleak.VerifyTestMain(m)
}
```
