# settle

Конкурентное выполнение функций на нативных итераторах Go: знакомые комбинаторы промисов, ограничение параллелизма над ленивым входом, повторы и восстановление порядка — из независимых кусочков, которые складываются друг с другом.

```go
// Обойти миллион ссылок, не больше 20 запросов одновременно,
// с повторами, а результаты записать пачками в исходном порядке.
results := settle.Map(ctx, urls, 20,
    func(ctx context.Context, url string) (page, error) {
        return settle.Retry(policy, settle.Timeout(5*time.Second, fetch(url)))(ctx)
    })

for chunk := range settle.Batch(settle.Ordered(results), 500) {
    save(chunk)
}
```

## Из чего собрано

Пакет — это **ядро** и две группы надстроек над ним. Надстройки о ядре ничего не знают, поэтому комбинируются свободно.

| Слой | Что делает | Состав |
| --- | --- | --- |
| **Ядро** | запускает задачи, задаёт контракт | `Stream`, `Map` |
| **Комбинаторы** | типовые правила поверх `Stream` | `AllSettled`, `All`, `Race`, `Any` |
| **Трансформеры** | преобразуют последовательность результатов | `Ordered`, `Values`, `Errors`, `Batch` |
| **Декораторы** | навешиваются на саму задачу | `Retry`, `Timeout`, `Observe` |

Ключевое свойство: декоратор — это обычная `func(ctx) (T, error)` на входе и на выходе, а трансформер — обычная последовательность на входе и на выходе. Поэтому любая комбинация осмысленна, и ни одна из них не требует опций в ядре.

## API

```go
// Ядро
func Stream[T any](ctx context.Context, fns ...func(context.Context) (T, error)) iter.Seq2[int, Result[T]]
func Map[In, Out any](ctx context.Context, in iter.Seq[In], n int,
    fn func(context.Context, In) (Out, error)) iter.Seq2[int, Result[Out]]
func FromChannel[T any](ctx context.Context, ch <-chan T) iter.Seq[T]

// Комбинаторы
func AllSettled[T any](ctx context.Context, fns ...func(context.Context) (T, error)) []Result[T]
func All[T any](ctx context.Context, fns ...func(context.Context) (T, error)) ([]T, error)
func Race[T any](ctx context.Context, fns ...func(context.Context) (T, error)) (T, error)
func Any[T any](ctx context.Context, fns ...func(context.Context) (T, error)) (T, error)

// Трансформеры
func Ordered[T any](seq iter.Seq2[int, Result[T]]) iter.Seq2[int, Result[T]]
func Values[T any](seq iter.Seq2[int, Result[T]]) ([]T, error)
func Errors[T any](seq iter.Seq2[int, Result[T]]) error
func Batch[T any](seq iter.Seq2[int, Result[T]], n int) iter.Seq[[]Indexed[T]]

// Декораторы
func Retry[T any](p RetryPolicy, fn func(context.Context) (T, error)) func(context.Context) (T, error)
func Timeout[T any](d time.Duration, fn func(context.Context) (T, error)) func(context.Context) (T, error)
func Observe[T any](h Hooks, fn func(context.Context) (T, error)) func(context.Context) (T, error)

// Задержки для RetryPolicy.Backoff — обычные последовательности
func Exponential(base time.Duration, factor float64, retries int) iter.Seq[time.Duration]
func Constant(d time.Duration, retries int) iter.Seq[time.Duration]
func Cap(seq iter.Seq[time.Duration], max time.Duration) iter.Seq[time.Duration]
func Jitter(seq iter.Seq[time.Duration], frac float64) iter.Seq[time.Duration]

type Result[T any] struct {
    Value T
    Err   error
}

type Indexed[T any] struct { // результат вместе с индексом своей задачи
    Index int
    Result[T]
}

type RetryPolicy struct {
    Backoff   iter.Seq[time.Duration] // длина = число ПОВТОРОВ; nil — без повторов
    Retryable func(error) bool        // nil — повторять любую ошибку
}

type Hooks struct {
    Start func()
    Done  func(elapsed time.Duration, err error)
}

type PanicError struct { // задача запаниковала; доставляется через Result.Err
    Value any
    Stack []byte
}
func (p *PanicError) Unwrap() error // panic(err) прозрачен для errors.Is / errors.As

var ErrGoexit error  // задача завершила горутину через runtime.Goexit (t.Fatal и т.п.)
var ErrNoTasks error // Race или Any вызваны без задач
```

## Контракт

Одинаков для `Stream` и `Map`, а значит и для всего, что построено поверх них.

- **Запуск ленивый.** Задачи стартуют не при вызове, а в момент обхода. Каждый новый обход последовательности запускает всё заново — результаты не мемоизируются.
- **Ровно один `Result` на задачу.** Паника внутри задачи не убивает процесс, а становится `*PanicError` в `Result.Err`; задача, завершившая горутину через `runtime.Goexit` (например, `t.Fatal` внутри теста), даёт `Result` с ошибкой `ErrGoexit`. Соседние задачи в обоих случаях не затрагиваются.
- **Индекс — это позиция задачи**, а не порядок завершения. Результаты приходят по мере готовности; за восстановление исходного порядка отвечает `Ordered`.
- **`break` = отмена.** Выход из цикла отменяет контекст незавершённых задач и дожидается их возврата. Результаты, «созревшие» после `break`, молча отбрасываются — включая ошибки и паники.
- **Задачи обязаны уважать `ctx`.** Отмена кооперативна: функция, игнорирующая контекст, будет дождана до обычного возврата. То же относится к входной последовательности `Map` — см. ниже.
- **`Result` не зануляет значение при ошибке.** В `Result.Value` приезжает ровно то, что вернула задача; осмысленность этого значения — договорённость между автором задачи и потребителем. Исключение — паника и `Goexit`: там возврата не существует, и значение всегда нулевое.
- **Структурная конкурентность.** К моменту выхода из цикла — обычного или через `break` — ни одна запущенная горутина уже не работает.

## Ядро: `Stream` или `Map`

Оба движка дают одинаковый контракт и различаются только расписанием.

| | `Stream` | `Map` |
| --- | --- | --- |
| Вход | список задач, известен заранее | ленивая `iter.Seq[In]` |
| Горутин | по одной на задачу, все сразу | не больше `n` одновременно |
| Когда брать | задач немного, все нужны сразу | задач много, очень много или заранее неизвестно сколько |

```go
// Stream: горстка разнородных задач, решение зависит от индекса.
loop:
for i, result := range settle.Stream(ctx, tasks...) {
    if result.Err != nil && required[i] {
        break loop // отменяет и дожидается остальных
    }
    handle(i, result)
}

// Map: однородная работа над длинным входом, лимит параллелизма.
for i, result := range settle.Map(ctx, slices.Values(paths), 8, hashFile) {
    handle(i, result)
}
```

`Map` намеренно не ставит барьеров: как только любая задача завершилась, освободившийся слот занимает следующий элемент входа. Этим он отличается от обхода пачками (`slices.Chunk` + `AllSettled`), где вся пачка ждёт самую медленную задачу в ней.

### Требование к входу `Map`

Отмена кооперативна не только для задач, но и для входа. Пока последовательность блокируется **внутри себя**, не отдавая очередной элемент, прервать её снаружи невозможно: у `iter.Seq` нет контекста, а Go не умеет прерывать чужой блокирующий вызов. Поэтому вход обязан либо завершаться сам, либо реагировать на отмену — иначе `Map` не вернётся из обхода, ровно как не вернётся, дожидаясь задачи, игнорирующей `ctx`.

Для срезов и любых конечных источников (`slices.Values` и подобные) требование выполняется само собой. Для источников, которые ждут данных — канал, курсор базы, очередь, — есть `FromChannel`, а свою последовательность нужно писать с `select` по `ctx.Done()`:

```go
func FromChannel[T any](ctx context.Context, ch <-chan T) iter.Seq[T]

ctx, cancel := context.WithCancel(ctx)
defer cancel()

for i, r := range settle.Map(ctx, settle.FromChannel(ctx, jobs), 8, handle) {
    // отмена ctx сворачивает и задачи, и чтение входа
}
```

Контекст источнику нужно передавать тот же, что и в `Map`: производную отмену, которую `Map` делает на `break`, наружу он не отдаёт.

## Комбинаторы

| Функция | Когда заканчивается | Результат | Пустой список |
| --- | --- | --- | --- |
| `AllSettled` | завершились все задачи | `[]Result[T]` в порядке аргументов; ошибки лежат рядом со значениями | пустой срез |
| `All` | завершились все или получена первая ошибка | `[]T` в порядке аргументов; при ошибке — `nil` и обёрнутая индексом причина | пустой срез, `nil` |
| `Race` | завершилась первая задача | её `(T, error)`, независимо от успеха | `ErrNoTasks` |
| `Any` | получен первый успех или упали все | первый успешный `T`; иначе `errors.Join` ошибок в порядке аргументов | `ErrNoTasks` |

«Первая ошибка» у `All` означает первую полученную по времени, поэтому её индекс при нескольких одновременных сбоях может различаться. `Any`, напротив, перед `errors.Join` раскладывает ошибки по исходным индексам, чтобы итоговый текст и обход `Unwrap() []error` были стабильны.

## Трансформеры

Чистые функции над последовательностью результатов. Работают поверх любого движка.

- **`Ordered`** — отдаёт результаты по возрастанию индекса, оставаясь последовательностью: результат `i` уходит потребителю сразу, как только пришли все меньшие индексы, а не после конца обхода. Цена — буфер: то, что «обогнало» ещё не пришедший меньший индекс, копится в памяти. Обратная сторона того же свойства — бэкпрешер: пока накопленное не отдано, источник не читается, а значит `Map` не берёт новые элементы входа.
- **`Values`** — успехи в порядке индексов плюс `errors.Join` всех неудач, обёрнутых индексами. В отличие от `All`, частичный успех не обнуляется.
- **`Errors`** — только объединённая ошибка, значения отбрасываются. Для задач-эффектов: разослать, инвалидировать, прогреть.
- **`Batch`** — нарезает поток на пачки по `n` для следующей стадии: батч-вставка в базу, отправка в очередь. Каждая пачка — свой срез, поэтому её можно отдать другой горутине без копирования.

```go
values, err := settle.Values(settle.Map(ctx, ids, 16, load))

for chunk := range settle.Batch(settle.Ordered(results), 500) {
    writeToDatabase(chunk) // позиция каждого элемента — в chunk[i].Index
}
```

## Декораторы

Оборачивают саму задачу, поэтому движок про них не знает и контракт не меняется.

```go
policy := settle.RetryPolicy{
    Backoff:   settle.Jitter(settle.Cap(settle.Exponential(200*time.Millisecond, 2, 5), 10*time.Second), 0.3),
    Retryable: isTransient, // 5xx, 429, таймауты — да; 400 и 404 — нет
}

task := settle.Retry(policy, settle.Timeout(5*time.Second, fetch(url)))
```

Задержки — обычная `iter.Seq[time.Duration]`, поэтому их можно строить и комбинировать как любую последовательность, а длина последовательности задаёт число **повторов** (не общее число вызовов).

Порядок обёрток задаёт смысл:

```go
settle.Retry(policy, settle.Timeout(2*time.Second, fetch)) // 2 секунды на КАЖДУЮ попытку
settle.Timeout(2*time.Second, settle.Retry(policy, fetch)) // 2 секунды на ВСЕ попытки разом
```

Паника внутри задачи не повторяется: это дефект кода, а не временный сбой — она летит дальше и становится `*PanicError` уже в движке.

## Что пакет делать не будет

Осознанные границы, чтобы `settle` не превращался в фреймворк:

- **Rate limiting и вежливость к хосту** — это `golang.org/x/time/rate`, и он навешивается декоратором ровно как `Retry`.
- **Знание про HTTP** — коды ответов, `Retry-After`, повторные тела запросов. `Retryable` принимает `error`, а классификацию пишет тот, кто знает свой протокол.
- **Дедупликация, персистентность, чекпоинты** — предметная логика приложения.
- **Опции у движка.** Всё, что можно выразить декоратором или трансформером, декоратором и трансформером и остаётся: иначе контракт ядра обрастает ветвлениями.

## Заметки о дизайне

- **Ядро без опций.** Два движка, один контракт; всё остальное — чистые функции снаружи. Новая возможность добавляется декоратором или трансформером, а не полем в конфиге.
- **Одна горутина на задачу** у `Stream`, как у промисов в JS. У `Map` — не больше `n` одновременно, слот освобождается сразу по завершении задачи.
- **Канал результатов с буфером**: у `Stream` он размером `len(fns)`, поэтому воркер никогда не блокируется на отправке. У `Map` длина входа заранее неизвестна, буфер равен `n`, и отправку страхует контекст — иначе задача повисла бы после ухода потребителя.
- **Отправка результата — в `defer`**: она происходит даже если задача завершает горутину через `runtime.Goexit`, поэтому потребитель никогда не зависает в ожидании недостающего результата.
- **Fan-in перед yield**: задачи пишут в канал; `yield` вызывает единственный цикл. Параллельные вызовы `yield` нарушают контракт итератора.
- **Порядок уборки важен**: при выходе сначала `cancel`, потом `wg.Wait`. См. пару `defer` в `Stream` и `Map`.
- **Повторы — на уровне задачи, а не движка.** Перезапуск пачки ради одной неудачной ссылки стоил бы всех остальных запросов, а индексы и учёт «ровно один результат» разъехались бы.

Go 1.23+ (итераторы range-over-func).

## Тестирование

```sh
go test -race ./...
```

Тесты проверяют гарантию отсутствия утечек, отслеживая число горутин. Для более строгой проверки подключите [goleak](https://github.com/uber-go/goleak):

```go
func TestMain(m *testing.M) {
    goleak.VerifyTestMain(m)
}
```
